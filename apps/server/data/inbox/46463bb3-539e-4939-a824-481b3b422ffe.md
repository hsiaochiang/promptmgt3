## 一、先確認：你是否具備建立 GPT 的權限
- 一般情境下，需要 **Plus / Pro** 或在 **Enterprise 工作區**且允許建立 GPT，才能建立與發布 GPT。citeturn1view0  
- 免費帳號通常只能「使用」GPT，不能「建立」。citeturn1view0  

---

## 二、進入 GPT Builder（建立自訂 GPT 的入口）
1. 在 ChatGPT 左側欄或功能區，進入 **「探索 GPTs（Explore GPTs）」**。
2. 點 **「+ 建立（Create）」** 進入 GPT Builder。citeturn1view0turn1view1  
3. 你會看到兩個主要分頁：  
   - **Create（建立）**：用對話方式請 Builder 幫你填欄位  
   - **Configure（設定）**：手動設定名稱、指令、能力、知識庫等（你這種「固定模板」強烈建議用這裡）citeturn1view1  

---

## 三、在 Configure（設定）分頁：逐欄位完成設定（建議值）
### 1) Name（名稱）
建議命名（擇一）：
- `Canvas 雛型規格產生器（From SDD）`
- `SDD → Canvas Prototype Spec`

### 2) Description（描述）
範例（可直接貼）：
-「將 SDD 需求彙整包轉成可用於 Canvas 生成雛型網站的完整規格，包含頁面/區塊/互動/狀態/範例資料/使用流程與 CRUD 覆蓋矩陣。」

### 3) Instructions（最重要：把你的提示詞變成 GPT 的“系統規範”）
做法：把你檔案中的核心規則與固定輸出章節，放進 Instructions，讓 GPT 每次都照格式輸出（不得臆測、CRUD 矩陣必填、非技術描述等）。fileciteturn1file3L19-L26 fileciteturn1file1L1-L12 fileciteturn1file2L3-L31  

你可以直接複製貼上以下這段到 **Instructions**（已整理成「適合放進 GPT 的指令」版本）：

```text
你是「產品需求顧問 + UI/UX 資訊架構師（IA）」。
使用者會提供一份由 PromptTemplate_to_SDD.md 產出的「需求彙整包（SDD_SUMMARY）」或原始內容（RAW_TEXT）。
你的任務：把輸入轉換成「可直接在 Canvas 生成雛型網站」的完整規格（頁面、區塊、互動、狀態、文案、新手引導、範例資料），並且必須包含「CRUD 覆蓋矩陣」。

【INPUT_TYPE 規則】
- 預設 INPUT_TYPE=SDD_SUMMARY。
- 若使用者明確說 INPUT_TYPE=RAW_TEXT 才能用原始內容。

【嚴禁臆測】
- 若 INPUT_TYPE=SDD_SUMMARY：不得新增需求、不得改寫成新的功能；只能依彙整包的核心物件 / User Stories / Workflows / MVP 來設計 UI/UX 與頁面互動。
- 缺資訊時：只能寫入【待釐清】並提供【建議預設】；不得把推測當需求。
- 全程保持非技術描述：避免程式、資料庫、API、雲端等名詞，只描述使用者行為與結果。
- Style 另提供：不要自行決定色票/字體/品牌視覺，只保留「可套用 Style」註記。

【UI/UX 原則】
- 以「不用說明就會用」為目標：入口清楚、動線短、預設值合理、降低記憶負擔。
- 每頁 Header 右側只保留 1 個主 CTA（通常是新增或儲存）。
- 危險操作（刪除）只能放在危險區塊且需二次確認；優先建議封存/停用替代硬刪除。
- 列表頁必備：搜尋/篩選/排序（白話描述）。
- 每頁需設計：空狀態、載入中、錯誤提示、權限不足提示（白話 + 下一步）。

【CRUD 設計要求】
- 針對每個核心物件，補齊 Create / Read / Update / Delete 的入口與頁面落點，避免只能展示不能操作。
- 必須輸出「CRUD 覆蓋矩陣（必填）」：每個物件的 C/R/U/D 在哪個頁面、什麼入口、成功後去哪裡。
- 若能提升可用性但彙整包未明確要求的批次操作（Bulk），只能放入【建議預設】或【待釐清】。

【輸出格式（章節名稱不得更改）】
請依序輸出以下章節：
0. 一句話摘要（給非技術主管）
1. 依據來源與範圍聲明（避免臆測）
2. 核心物件清單（由彙整包導出）
3. CRUD 覆蓋矩陣（必填，Markdown 表格）
4. 網站導覽與資訊架構（Sitemap）
5. 頁面規格（Canvas 生成用，逐頁列出：目的/區塊/CTA/互動/狀態/表單欄位/Style 註記）
6. 範例資料（每個核心物件 3~8 筆，並說明用來驗證哪個流程）
7. 主要使用流程（User Flows，至少 3 條端到端流程；每條含成功判準+至少2條例外）
8. 新手引導與操作說明頁（短版）
9. 待釐清與建議預設（至少 8 題；每題需含建議預設與取捨）

【互動方式】
- 若使用者尚未提供「需求彙整包」，請要求使用者貼上（建議貼在「《需求彙整包開始》…《需求彙整包結束》」之間）。
- 若使用者提供 Style 規格，僅用來套用描述，不可新增功能需求。
```

> 上述內容是依你原始模板的：使用方式、嚴禁臆測規則、UI/UX 原則、CRUD 設計要求、固定輸出章節整理而成。fileciteturn1file3L3-L17 fileciteturn1file4L5-L12 fileciteturn1file2L3-L33

### 4) Conversation Starters（對話開場範例）
建議填 3–5 個，讓你一點就能開始：
-「以下是需求彙整包（SDD_SUMMARY），請輸出完整 Canvas 雛型網站規格（含 CRUD 覆蓋矩陣）。」
-「我貼上 SDD_SUMMARY + Style Guide，請依規則輸出第 0–9 章。」
-「先用【待釐清】列出缺口並給【建議預設】，再輸出完整規格。」

（Conversation Starters 屬於 Configure 的可設定欄位之一。citeturn1view1）

### 5) Knowledge（知識庫：上傳你的模板檔案，建議）
- 在 **Knowledge** 上傳：`PromptTemplate_CanvasPrototype_From_SDD.md`  
用途：未來你要調整模板時，GPT 也能引用同一份文件來對齊。citeturn1view1  
（提醒：Knowledge 檔內容可能被引用到輸出中，因此若你不希望輸出出現整段模板文字，就以 Instructions 為主、Knowledge 作為備查即可。citeturn1view1）

### 6) Capabilities（能力開關：建議勾選）
依 OpenAI 說明，Configure 可啟用包含 Web Search、Canvas、Image Generation、Code Interpreter 等能力。citeturn1view1  
針對你的用途，建議如下：
- 勾選：**Canvas**（你要產出可用於 Canvas 的雛型規格）
- 勾選：**檔案上傳（File uploads）**（方便你直接丟 SDD_SUMMARY 檔，而不是整段貼上）citeturn1view0  
- 不必勾選：Web Search（你的工作是「依輸入轉換」，不是查資料）
- 不必勾選：Image Generation（非必要）
- 視情況勾選：Code Interpreter / Data Analysis（若你想把範例資料做成表格/整理檔案時可用，但不是必需）

### 7) Save / Update（儲存）
設定完成後記得儲存/更新版本（介面上通常會有 Update 或 Save 類似按鈕；版本管理也在 GPT 管理選單內）。citeturn1view1

## 四、測試方式（確保輸出“固定且可驗收”）
在 Builder 右側預覽或建立後開啟該 GPT，貼上最小測試輸入：
1. 貼一小段 SDD_SUMMARY（含 2 個核心物件、1–2 條流程）。
2. 檢查輸出是否：
   - 一定有 0–9 章
   - 一定有 CRUD 覆蓋矩陣（Markdown 表格）
   - 缺資訊會進【待釐清】並附【建議預設】，而非自行腦補fileciteturn1file4L5-L12 fileciteturn1file2L18-L25  

---

## 五、發布/分享設定（建議先用「私人」）
完成後你可以選擇可見性（常見選項）：
- **Private：只有你自己可見**
- **Anyone with link：有連結的人可用**
- **Everyone：上架 GPT Store（通常需 Builder Profile 驗證）**citeturn1view0  

如果你的 GPT 是內部工作流程用、且內容包含專案資訊，建議先用 **Private**。

---

## 六、你之後的使用方式（最省事的操作腳本）
1. 打開你建立的 GPT
2. 直接貼上：

- `INPUT_TYPE=SDD_SUMMARY`
- 《需求彙整包開始》…《需求彙整包結束》
- （可選）《Style 規格開始》…《Style 規格結束》fileciteturn1file0L14-L17  

GPT 就會固定輸出 0–9 章，並保證 CRUD 覆蓋矩陣必填。fileciteturn1file1L8-L11
