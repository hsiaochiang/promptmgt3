# High-Level Goal
打造一套「以檔案為核心」的 AI 提示詞資產管理系統，讓使用者能把分散在各種對話平台與工作流程中的提示詞，快速匯入、整理、分類、版本留存，並在日常撰寫與複用時維持一致的品質與可追溯性。

# User Stories
## 1) 專案與提示詞資產管理
- As a 使用者, I want to 建立並維護多個專案來分群管理提示詞, So that 我能用專案脈絡快速定位與復用提示詞。
- As a 使用者, I want to 在專案中以列表/看板方式檢視進度, So that 我能用視覺化方式掌握工作狀態與優先順序。
- As a 使用者, I want to 對專案與提示詞進行新增、編輯、封存、還原、刪除, So that 我能維持資料乾淨並區分現役與歷史資產。

## 2) 撰寫與編輯體驗
- As a 使用者, I want to 在同一個編輯介面中同時管理「正文」與「中繼資料」, So that 提示詞本體與分類資訊能同步維護且可讀。
- As a 使用者, I want to 支援常用的標記語法、即時預覽、與自動儲存, So that 我能用接近寫作的節奏快速迭代提示詞。
- As a 使用者, I want to 直接拖曳圖片/附件到編輯區, So that 系統能自動整理附件並在內容中產生可引用連結。

## 3) 剪貼簿與常用片語（Snippets）
- As a 使用者, I want to 在編輯提示詞時快速插入常用指令模組（角色、格式、限制、風格）, So that 我能用模組化方式提升一致性與效率。
- As a 使用者, I want to 以「分類瀏覽」與「最近使用」方式管理片語, So that 我能用最少操作完成插入與複用。

## 4) 外部對話匯入（Inbox）
- As a 使用者, I want to 將各種對話平台中的對話內容一鍵匯入為待整理項目, So that 我能把靈感與可用提示詞先收進暫存區，稍後再歸檔。
- As a 使用者, I want to 在暫存區檢視並做最小幅度編修（例如補標題、刪除敏感段落）, So that 我能在歸檔前完成必要清理。
- As a 使用者, I want to 把暫存區項目歸檔到指定專案/分類並補齊標籤, So that 內容能回到可維護的長期資產結構中。

## 5) 編輯器外掛協作（貼標籤與歸檔）
- As a 使用者, I want to 在我的程式碼編輯器中由 AI 協助為提示詞補上標籤、狀態、優先級與歸檔位置, So that 我能以「檔案為中心」完成整理，不必回到主介面逐筆處理。
- As a 使用者, I want to 由外掛執行「移動檔案/改名/更新中繼資料」後，主介面能立即反映變更, So that 我能保持單一真實來源且不需要手動重新整理。

## 6) 搜尋與快速定位
- As a 使用者, I want to 在全域搜尋框中同時搜尋標題、標籤與全文內容, So that 我能用最短路徑找到需要的提示詞或專案。
- As a 使用者, I want to 透過標籤與狀態快速篩選, So that 我能建立自己的工作視角（例如只看待優化、只看高優先級）。

## 7) 版本歷史與備份
- As a 使用者, I want to 在重要事件後自動留下可回溯的版本節點, So that 我能在錯誤操作或需求回溯時找回內容。
- As a 使用者, I want to 在設定頁一鍵觸發立即備份, So that 我能在重大整理後確保資料已安全留存。
- As a 使用者, I want to 在編輯器中查看某份文件的歷史紀錄, So that 我能理解它的演進並追蹤改動原因。

## 8) 設定與治理
- As a 使用者, I want to 設定資料根目錄與附件目錄, So that 我能把資產放在我習慣管理與同步的位置。
- As a 使用者, I want to 管理全域標籤（新增、改名、刪除、合併）與顏色分類, So that 標籤體系可長期演進且保持一致。
- As a 使用者, I want to 自訂「模型/來源」等下拉選項, So that 資料描述能符合我的實際工作環境。

- 資料根目錄
- 附件目錄
- 全域標籤字典（含顏色與分類）
- 可選的模型/來源清單

- 來源連結（可為對話/分享連結）

## Snippet

- 事件時間
- 事件訊息
- 受影響範圍（工作區/專案/提示詞/暫存項目）

# Workflows
## A) 建立專案並整理提示詞
1. 使用者新增專案，填寫標題、摘要、標籤與狀態。
2. 使用者在專案下新增提示詞，填寫標題、狀態、優先級、標籤與正文。
3. 使用者持續編輯，系統自動保存並更新「最後更新時間」。
4. 使用者可封存/還原專案或提示詞；封存後預設不出現在主要列表。

## B) 提示詞編輯（含中繼資料與附件）
1. 使用者開啟某提示詞的詳細頁。
2. 使用者編輯標題、狀態、標籤、備註與正文內容。
3. 使用者拖曳圖片/附件進入編輯區。
4. 系統將附件放入指定目錄並在內容中插入引用連結。
5. 系統以防抖機制自動保存內容與中繼資料。

## C) 使用剪貼簿片語快速組裝提示詞
1. 使用者在編輯提示詞時打開片語浮層。
2. 使用者以分類瀏覽或最近使用找到片語。
3. 點擊片語後，系統將片語插入至游標位置並記錄最近使用。

## D) 從外部對話平台匯入到 Inbox
1. 使用者在對話平台頁面觸發「匯入」。
2. 系統將對話整理成可讀的文字文件並附上來源資訊，放入暫存區。
3. 主介面顯示新匯入項目，允許最小幅度編修（標題/刪減/註記）。

## E) 由編輯器外掛執行歸檔與貼標籤
1. 使用者在編輯器中選取暫存區項目或提示詞檔案。
2. 外掛呼叫 AI 產生建議：標籤、狀態、優先級、歸檔目的地與命名。
3. 使用者接受/微調建議。
4. 外掛執行歸檔：更新中繼資料、移動檔案到目標位置、必要時改名。
5. 主介面即時收到變更並更新側邊欄與列表/看板。

## F) 版本節點與歷史檢視
1. 在「匯入成功/歸檔/刪除」等重要事件後，系統自動建立一個版本節點。
2. 每日首次啟動或關閉時，若存在未納入版本節點的變更，系統建立每日快照。
3. 使用者可在詳細頁查看該文件的歷史列表並開啟舊版本內容檢視（進階）。

## G) 全域搜尋
1. 使用者在頂部搜尋框輸入關鍵字。
2. 系統回傳符合的專案/提示詞/暫存項目（含標題、標籤、摘要片段）。
3. 使用者點擊結果直接開啟詳細頁。

# Predefined Data
- 使用者角色：
  - Owner（單人使用情境，可視為管理者）
  - Collaborator（預留：多人共用時的權限角色）
- 專案狀態：規劃中、進行中、暫停、完成
- 提示詞狀態：草稿、待優化、可用、停用
- 標籤分類：平台標籤、交付物標籤、受眾標籤、共通標籤
- 片語預設分類：角色設定、格式要求、限制條件、風格指令、未分類
- 系統預設片語（可編輯）：繁體中文限制、表格輸出格式、常見角色設定

# Tech Stack
## Web App（主介面）
- Language: TypeScript 5.4+
- Framework: React 18.x
- Build Tool: Vite 5.x
- Styling: Tailwind CSS 3.x
- Icon: lucide-react
- Editor: CodeMirror 6（Markdown + Frontmatter/YAML + history）
- Markdown Rendering: remark + rehype（含 GFM、程式碼高亮）

## Local Server（本機服務）
- Runtime: Node.js 20 LTS
- HTTP Framework: Fastify 4.x（或 Express 4.x；建議 Fastify）
- WebSocket: ws
- File Watcher: chokidar
- Git Wrapper: simple-git
- Validation: zod
- Logging: pino
- Packaging（可選）: 将 Web 與 Server 打包為單一可執行（Reference: `research.md`）

## Chrome Extension（匯入對話）
- Manifest: MV3
- Language: TypeScript
- Components:
  - Content Script：抽取對話 DOM 結構
  - Service Worker：送出匯入請求、管理 token
  - UI：Popup（匯入/設定/狀態）

## VS Code Extension（貼標籤/歸檔）
- Language: TypeScript
- VS Code API: Extension API + FileSystemWatcher + Commands
- AI 協作模式（兩種都支援）:
  - Mode A（優先）：生成「可貼到 Copilot/Codex 的指令模板」，並解析回傳的 YAML/JSON 建議後套用到檔案
  - Mode B（可選）：呼叫本機服務提供的 /api/ai/suggest（Reference: `research.md`）

# Architecture
## Overall
- Architecture Style: Modular Monolith（本機服務單體 + 兩個外掛客戶端）
- API Style: REST + WebSocket events
- Source of Truth: File System（所有專案/提示詞/暫存內容以檔案保存）
- Derived Index: Search/Metadata index（由本機服務掃描與監聽建立）

## Components & Responsibilities
1) Web App
- 顯示：專案列表/看板、提示詞列表/看板、暫存區、剪貼簿、設定
- 編輯：提示詞/專案/暫存項目的內容與中繼資料
- 互動：拖曳附件、Popover 片語插入、全域搜尋、歷史檢視

2) Local Server
- 檔案存取：讀寫、搬移、重新命名、附件落盤
- 監聽同步：監聽資料根目錄變更並以 WebSocket 推播前端更新
- 匯入入口：接收瀏覽器外掛上傳內容，寫入暫存區
- 版本控管：在重要事件/每日快照/手動備份時執行 commit/push
- 搜尋：維護全文索引並提供查詢 API

3) Chrome Extension
- 從 ChatGPT / Gemini 頁面抽取對話（標題、訊息、角色、時間、來源連結）
- 轉換為 Markdown + Frontmatter（來源資訊、匯入時間、平台）
- POST 到本機服務 /api/inbox/import

4) VS Code Extension
- 監控 inbox 與 projects 目錄變更（與 Web App 一致）
- Commands:
  - Prompt: Suggest Tags/Status/Priority（產生可貼給 Copilot/Codex 的指令模板）
  - Prompt: Apply Suggestions（解析並套用回傳建議）
  - Inbox: Archive Item（搬移到指定專案、更新 frontmatter、重命名）
- 與本機服務共用同一套「檔案命名/目錄規則」與「中繼資料格式」

  - GET /api/projects
  - GET /api/prompts
- Inbox
  - GET /api/inbox
  - POST /api/inbox/import
  - POST /api/inbox/mark-cleaned
- Search
  - GET /api/search?q=
- Git
  - GET /api/git/status
  - GET /api/git/log?path=
  - POST /api/git/commit
  - POST /api/git/push
- Settings
  - GET /api/settings
  - POST /api/settings
- WebSocket Events
  - file.created / file.updated / file.deleted / file.moved
  - inbox.imported
  - git.committed

## Security（本機仍需基本防護）
- Extension-to-Server：使用一次性配對碼換取 API token（儲存在 extension storage）
- Server 僅允許 localhost 存取；CORS 白名單；token 必填
- 檔案操作需做 path traversal 防護（僅允許在 Project Root 之下）

# Database Design
> 原則：檔案是唯一真實來源；資料庫僅作為「索引/快取」，可隨時重建。

## Option A（建議）：SQLite + FTS5
- 適用：全文搜尋、快速篩選、可回傳 snippet
- Tables（概念）
  - files(id, path, type, title, updatedAt, checksum)
  - prompts(id, path, projectId, status, priority, model, sourceLink, archived, updatedAt)
  - projects(id, path, status, projectType, archived, updatedAt)
  - tags(id, name, category, color)
  - prompt_tags(promptId, tagId)
  - snippets(id, title, category, content, lastUsedAt)
  - inbox(id, path, source, sourceLink, importedAt, cleanedState)
  - fts_content (virtual table; indexed fields: title, tagsText, body)

## Option B（替代）：純檔案掃描 + in-memory index
- 適用：資料量小；啟動掃描成本可接受
- 缺點：全文搜尋速度與體驗較不穩定

# Implementation Steps
## Phase 0 — Repo & 規範定義
1. 建立 monorepo：/apps/web, /apps/server, /extensions/chrome, /extensions/vscode
2. 定義資料目錄規範（Project Root 結構、Inbox、Assets）
3. 定義檔案格式規範（Frontmatter schema：Project/Prompt/InboxItem/Snippet）
4. 寫入 SpecKit Constitution（見下方 UI/UX 憲章建議）

## Phase 1 — Local Server MVP
1. Settings：讀寫 Project Root / Assets Path
2. Files API：read/write/move/rename + attach
3. Watcher：chokidar 監聽 root，WebSocket 推播事件
4. Inbox import：/api/inbox/import 寫檔到 inbox
5. Scanner：啟動時掃描所有檔案建索引（先做 Option B，後續可切 Option A）

## Phase 2 — Web App MVP（對齊 prototype 的操作習慣）
1. Sidebar + Sections：Projects/Prompts/Clipboard/Settings
2. Projects：列表/看板/封存
3. Prompts：列表/看板/封存
4. Detail Panel：右側滑入、可展開全頁、Breadcrumb
5. Editor：正文 + 中繼資料編輯（含 auto-save debounce）
6. Clipboard：Popover 插入 + 最近使用
7. Inbox：列表 + 簡修 + 開啟檔案（歸檔先留給 VS Code extension）

## Phase 3 — Search & Index
1. 全域搜尋框：title/tag/body
2. 建立索引服務（Option A 上線：SQLite FTS5）
3. 回傳 snippet 與 highlight（提升命中可讀性）

## Phase 4 — Version Control
1. 重要事件觸發 commit（匯入成功、歸檔、刪除）
2. 每日快照：啟動/關閉時檢查 dirty 狀態
3. History View：顯示 log；舊版本檢視列為 Nice-to-have
4. Settings：立即備份（commit & push）+ remote 設定

## Phase 5 — Chrome Extension（匯入）
1. Content script：抽取對話（支援 ChatGPT / Gemini）
2. 轉換器：輸出 Frontmatter + 對話段落格式
3. 配對流程：輸入本機服務位址 + token
4. 匯入按鈕：單次匯入 + 匯入成功提示

- As a 使用者, I want to 一鍵觸發立即備份, So that 我能在大整理後確保資料安全。
- As a 使用者, I want to 查看該資產的歷史列表並可開啟舊版內容, So that 我能理解演進並在需要時回復。

## D) data-model.md 修改建議（目前像 DB schema，需要轉成「檔案/契約導向」）

data-model 現在列實體與欄位很齊，但看起來偏「資料庫表格」語感；對你這案子「檔案是權威」來說，還缺 3 個關鍵：  
1) **檔案映射（每種實體對應到什麼檔案/目錄）**  
2) **frontmatter 欄位定義（哪些欄位屬於中繼資料區塊）**  
3) **事件/索引如何重建（掃描規則 + watcher event payload）**  
fileciteturn1file0

### D1. 新增「File Mapping」段落（強烈建議）
例如：

- Project：`/projects/<projectSlug>/project.md`
- Prompt：`/projects/<projectSlug>/prompts/<promptSlug>.md`
- InboxItem：`/inbox/<yyyy-mm-dd>/<id>.md`
- Snippet：`/snippets/<category>/<id>.md`
- Attachments：`/assets/<yyyy>/<mm>/<filename>`

> 這會讓 agent 在實作 CRUD 時不會「臨時自己發明路徑」。

### D2. Frontmatter schema 要寫清楚（含必填/選填/預設值）
目前欄位有 `id(uuid/slug)`，但你實作上很可能會混用。 fileciteturn1file0  
建議明確定義：
- `id`（穩定 uuid） vs `slug`（檔名/路徑用）
- `updatedAt` 是系統寫入還是 UI 控制
- enums 的合法值與預設值

### D3. 把 InboxItem 的 `suggestedTarget` 改成純引用（避免「Project|Prompt」這種型別）
建議改成：
- `suggestedTarget: { projectId?: string; promptId?: string; pathHint?: string }`
因為「外部工具歸檔」的世界裡，最可靠的是「路徑/識別碼」，不是 union 物件。

### D4. VersionEvent 增加「Retention Policy」與「Snapshot Layout」
你已經有 `snapshotPath`，但未定義：
- 快照目錄結構（是否含 assets 子目錄）
- 保留天數/上限（避免磁碟爆）
