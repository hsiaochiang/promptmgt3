## 改寫能解決什麼

### 1) 把雛形變成「可被遵循的 Reference Implementation」
你現在的 `app.jsx` 是完整可跑的雛形，但對 Coding Agent 來說仍有大量自由度：它可以用不同元件拆法、不同 spacing、不同按鈕語意去「重做一次」，結果就容易漂移。

- **固定的版面骨架（AppShell / PageHeader / ContentLayout）**
- **固定的元件集合（Button / Table / BoardColumn / EditorSection）**
- **固定的樣式 token（字級、間距、邊線、陰影、表格格線規則）**

讓 Agent 後續開發只是在「既定骨架」上加資料/邏輯，不是在重新設計 UI。

- 「列表頁必須使用 `DataTable`，欄位由 schema 決定」
- 「看板必須使用 `Board`，狀態欄順序固定」

這會把 UI 變成“可編排的積木”，而不是“需重新設計的畫面”。

### 3) 驗收成本下降：改成「對照元件／token」而不是「比對整頁」
你要的其實是「和雛形一致」。如果 UI 被拆成固定元件與 token，你驗收時只需要看：
- 是否用對元件
