# Feature Specification: 檔案為核心的提示詞資產管理主系統

**Feature Branch**: `001-prompt-asset-hub`  
**Created**: 2026-01-04  
**Status**: Draft  
**Input**: User description: "打造一套以檔案為核心的提示詞資產管理主系統，能在同一處完成專案/提示詞整理、撰寫、分類、搜尋、封存、版本備份與外部整合入口"

## Clarifications

### Session 2026-01-04

- Q: 使用者模式與權限是否需要登入/角色管控？ → A: 單人本機模式；不做登入/權限，僅需檔案/路徑存取檢查。
- Q: 版本/快照是否需複製附件？ → A: 每個版本/每日快照都複製正文＋中繼資料＋附件完整複本，避免附件遺失或覆蓋。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 專案/提示詞管理與自動保存 (Priority: P1)

使用者可在同一介面建立/編輯/封存/刪除專案與提示詞，於詳細頁同時維護正文與中繼資料，並於停止輸入後自動保存。

**Why this priority**: 直接支撐核心資產管理與日常創作流程，沒有此能力無法形成 MVP。

**Independent Test**: 在乾淨工作區設定資料根目錄後，建立專案與提示詞、編輯正文＋中繼資料，驗證列表/詳情顯示正確且自動保存生效。

**Acceptance Scenarios**:

1. **Given** 已設定資料根目錄與附件目錄，**When** 新增專案並填寫標題、摘要、標籤，**Then** 專案出現在列表/看板，屬性與時間戳正確儲存。
2. **Given** 已開啟提示詞詳情頁，**When** 編輯正文與中繼資料並停止輸入 2 秒，**Then** 系統自動保存並顯示保存成功時間；重新載入後內容一致且無遺失。
3. **Given** 需要封存提示詞，**When** 對提示詞執行封存，**Then** 該項目從主要視圖隱藏並可於封存視圖查詢。

---

### User Story 2 - 視圖切換與搜尋/篩選 (Priority: P2)

使用者可在列表與看板視圖間切換，並以關鍵字、狀態、優先級、標籤搜尋或篩選資產以快速定位。

**Why this priority**: 提升導航效率，支援不同工作視角，直接影響可用性。

**Independent Test**: 建立多筆專案與提示詞後，切換視圖並執行搜尋/篩選，驗證結果集與顯示狀態正確且切換狀態持續記憶。

**Acceptance Scenarios**:

1. **Given** 列表已載入多筆提示詞，**When** 搜尋關鍵字或標籤，**Then** 結果只包含符合標題/標籤/正文的項目並高亮匹配片段。
2. **Given** 使用者位於列表視圖，**When** 切換至看板，**Then** 資產依狀態/優先級泳道呈現，並保留已套用的篩選條件；返回列表後條件仍生效。

---

### User Story 3 - 版本備份與歷史檢視 (Priority: P3)

使用者可在重要事件後建立版本節點，每日自動快照，並一鍵觸發立即備份；可查看歷史列表並開啟舊版內容。

**Why this priority**: 確保內容安全與可回溯，降低誤刪或誤編輯的風險。

**Independent Test**: 在單一提示詞上建立多次編輯與手動備份，驗證每日快照任務與歷史列表可顯示並開啟指定版本。

**Acceptance Scenarios**:

1. **Given** 系統已設定備份目錄，**When** 使用者點擊「建立版本節點」，**Then** 新節點記錄標題/時間/摘要並出現在歷史列表，可開啟檢視。
2. **Given** 每日排程啟用，**When** 到達排程時間，**Then** 產生當日快照並顯示於歷史列表；若失敗，顯示錯誤並可重試。
3. **Given** 使用者進行大量編輯後，**When** 觸發立即備份，**Then** 建立最新快照且不阻塞編輯流程。

---

### User Story 4 - 暫存區檢視與簡修 (Priority: P3)

使用者可檢視匯入的暫存項目，對標題/刪減/註記進行最小幅度編修，並看到明確提示：歸檔由外部工具處理。

**Why this priority**: 讓外部匯入流程有落地入口，同時避免混淆歸檔責任。

**Independent Test**: 建立多筆暫存項並開啟暫存區，編輯標題與註記，確認提示文案與資料保存正確。

**Acceptance Scenarios**:

1. **Given** 暫存區有新匯入項目，**When** 使用者開啟暫存區，**Then** 項目依時間排序並顯示來源與建議標籤。
2. **Given** 使用者對暫存項目修改標題或備註，**When** 保存後，**Then** 變更立即反映且顯示提醒「歸檔由外部工具處理」。

### Edge Cases

- 外部檔案異動（新增/移動/刪除）與本地編輯衝突時，需提示衝突並允許重新整理或覆寫。
- 附件同名或缺少附件目錄時，需自動改名或提示設定錯誤，避免覆蓋。
- 搜尋/篩選無結果時，顯示「無結果」並允許清除條件。
- 自動保存/備份失敗時，提供重試與錯誤訊息，不阻塞編輯。
- 快照配額不足或儲存空間不足時，提示並導引清理或更換目錄。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須允許建立、編輯、封存、刪除專案與提示詞，並保存標題、摘要/正文、狀態、優先級、標籤、備註、來源連結、更新時間。
- **FR-002**: 專案與提示詞列表須支援列表/看板視圖切換，並記住上次視圖狀態與套用的篩選條件。
- **FR-003**: 提示詞詳情頁必須支援正文與中繼資料同頁編輯，並在停止輸入 ≤ 2 秒內自動保存，顯示成功時間/失敗訊息。
- **FR-004**: 支援拖曳圖片/附件到編輯區，系統需移動至附件目錄、產生檔名並插入引用連結。
- **FR-005**: 提供搜尋與篩選：可依標題、標籤、正文全文檢索，並以狀態、優先級、標籤快速篩選；結果應可直接開啟詳情。
- **FR-006**: 暫存區必須顯示匯入項目並允許編輯標題/刪減/註記，清楚提示「歸檔由外部工具處理」，不提供歸檔操作。
- **FR-007**: 版本與備份：允許手動建立版本節點、每日自動快照、立即備份；歷史列表可按時間檢視並開啟指定版本內容。
- **FR-008**: 系統需偵測資料根目錄的新增/修改/搬移/刪除並即時更新側邊欄、列表/看板與詳情顯示。
- **FR-009**: 設定頁需允許設定資料根目錄、附件目錄、全域標籤（新增/改名/刪除/合併）、常用選項清單、備份設定；設定需驗證路徑與衝突。
- **FR-010**: 所有操作需提供回饋：保存/備份/同步成功與錯誤訊息，錯誤不應阻塞其他可行操作。
- **FR-011**: 系統採單人本機模式，無登入/角色/權限管理；僅檢查資料根目錄與附件目錄存在且具讀寫權限，若無權限需提示並阻止寫入。
- **FR-012**: 版本節點與每日快照需保存正文、中繼資料與附件的完整複本；建立時若附件缺失或無法複製需提供錯誤與重試。

### Key Entities *(include if feature involves data)*

- **Workspace**: 根目錄、附件目錄、全域標籤字典、常用選項、備份設定、外部整合授權資訊。
- **Project**: 識別碼、標題、摘要、狀態、專案類型、標籤、關聯檔案、更新時間、封存狀態。
- **Prompt**: 識別碼、所屬專案、標題、狀態（草稿/待優化/可用/停用）、優先級、標籤、來源連結、備註、正文、更新時間、封存狀態。
- **Snippet**: 識別碼、標題、分類、內容、最近使用時間（供片語快速插入）。
- **InboxItem**: 識別碼、標題、來源平台/連結、匯入時間、原始內容、清理狀態、建議歸檔目的地與標籤。
- **Attachment**: 檔名、類型、來源、儲存位置、關聯對象（Project/Prompt/InboxItem）。
- **VersionEvent**: 事件類型（匯入成功/歸檔/刪除/每日快照/手動備份）、事件時間、訊息、受影響範圍。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可在 2 分鐘內完成「建立專案＋新增提示詞＋編輯正文與中繼資料」並成功自動保存；重新開啟後內容無遺失。
- **SC-002**: 搜尋/篩選在 5,000 筆資產內 95% 查詢於 1 秒內返回並允許直接開啟結果。
- **SC-003**: 每日自動快照成功率每週 ≥ 99%，手動/立即備份成功率 100%；歷史列表可開啟任一近 30 天版本。
- **SC-004**: 暫存區檢視與簡修操作 95% 在 3 秒內完成保存；提示文案讓 90% 使用者明確理解歸檔由外部工具處理（以可用性測試量表 ≥ 4/5）。
