## 澄清（Clarifications）

### Session 2026-01-04

- Q: 使用者模式與權限是否需要登入/角色管控？ → A: 單人本機模式；不做登入/權限，僅需檔案/路徑存取檢查。
- Q: 版本/快照是否需複製附件？ → A: 每個版本/每日快照都複製正文＋中繼資料＋附件完整複本，避免附件遺失或覆蓋。

### Session 2026-01-05

- Q: 「刪除」是否為永久刪除？ → A: 刪除 = 移到回收站（`<rootPath>/.pah/trash/`），可復原；封存仍為 `archived=true` 的隱藏狀態。
- Q: 刪除移到回收站時，該實體的附件如何處理？ → A: 一併移動該實體的附件資料夾（`<attachmentPath>/<entityType>/<entityId>/`）到回收站；復原時一併移回。
- Q: 回收站（trash）要不要自動清理？ → A: 要；預設保留 30 天（可設定），到期自動刪除。
- Q: 從回收站復原時若目的地已存在同名/同路徑檔案（或附件資料夾）要怎麼處理？ → A: 阻擋並提示使用者選擇：覆蓋 / 改名 / 取消。
- Q: 回收站（trash）在 UI 上要怎麼呈現？ → A: 提供「回收站」視圖（Sidebar 入口），可搜尋/篩選並執行復原/永久刪除。

### Session 2026-01-06

- Q: Settings.tagsDict 刪除 tag 時，是否要批次改寫既有檔案移除該 tag？ → A: 不批次改寫既有檔案；僅更新 tagsDict（影響建議/選單），既有檔案中的 tags 保留。
- Q: backup.schedule 的格式要採用哪一種？ → A: 使用每日時間 `HH:mm`（24 小時制，本機時區）。
- Q: 回收站復原的 `strategy=rename` 時，`newSlug` 的適用範圍？ → A: `newSlug` 僅替換原本的 slug（同一路徑位置復原）；不支援跨專案搬移復原。
- Q: 回收站自動清理（retention）要怎麼觸發？ → A: server 啟動時先跑一次，之後每日固定時間跑（例如 03:00，本機時區）。
- Q: 儲存 settings 時，`rootPath`/`attachmentPath` 不存在要怎麼處理？ → A: 直接回 400 並要求使用者先建立資料夾；server 不自動建立目錄。
- Q: Sidebar 導覽要嚴格照 prototype（僅 Projects/Prompts/Clipboard/Settings）還是需納入規格入口（Inbox/Archive/Trash）？ → A: 採混合：保留 prototype 的 Projects/Prompts 四項（列表/看板），並在 Tools 區加入 Inbox/Archive/Trash；Clipboard/Settings 仍保留。
- Q: Archive 要作為 Tools 的獨立入口，或是 Projects/Prompts 的封存子視圖？ → A: Archive 是 Tools 的獨立入口（activeSection=archive），進去後以單一頁面同時顯示已封存專案 + 已封存提示詞（含類型篩選切換）。
- Q: Project.status 的允許值要採用哪一組？ → A: `planned | in_progress | paused | done`（對齊 prototype 的 4 欄）。
- Q: Prompt.status 的允許值要採用哪一組？ → A: `draft | needs_review | ready | deprecated`。
- Q: Prompt.priority 的允許值要採用哪一組？ → A: `high | medium | low`（固定枚舉）。
- Q: FR-002「記住上次視圖狀態與篩選條件」的狀態要存哪裡？ → A: 寫入 WorkspaceSettings（走 API 落盤）；不使用 localStorage 作為權威狀態來源。
- Q: Tools → Archive（已封存）視圖要顯示哪些內容？ → A: 同一頁顯示已封存專案 + 已封存提示詞，並可用篩選切換類型。
- Q: Snippet（剪貼簿/常用片語）要如何落盤？ → A: 以檔案落盤：每個 Snippet 一個檔，放在 `<rootPath>/.pah/snippets/`；掃描可重建。
- Q: UI-003 的 Detail Panel 要用固定右欄或 overlay？ → A: 使用 overlay 右滑面板（有 backdrop，點背景可關閉），不佔固定欄位。

## 使用情境與測試（必填）

### 使用者故事 1 - 專案/提示詞管理與自動保存（優先級：P1）

使用者可在同一介面建立/編輯/封存/刪除專案與提示詞，於詳細頁同時維護正文與中繼資料，並於停止輸入後自動保存。

**為何是此優先級**：直接支撐核心資產管理與日常創作流程，沒有此能力無法形成 MVP。

**獨立驗收**：在乾淨工作區設定資料根目錄後，建立專案與提示詞、編輯正文＋中繼資料，驗證列表/詳情顯示正確且自動保存生效。

**驗收情境**：

1. **前提** 已設定資料根目錄與附件目錄，**當** 新增專案並填寫標題、摘要、標籤，**則** 專案出現在列表/看板，屬性與時間戳正確儲存。
2. **前提** 已開啟提示詞詳情頁，**當** 編輯正文與中繼資料並停止輸入 2 秒，**則** 系統自動保存並顯示保存成功時間；重新載入後內容一致且無遺失。
3. **前提** 需要封存提示詞，**當** 對提示詞執行封存，**則** 該項目從主要視圖隱藏並可於封存視圖查詢。

---

### 使用者故事 2 - 視圖切換與搜尋/篩選（優先級：P2）

使用者可在列表與看板視圖間切換，並以關鍵字、狀態、優先級、標籤搜尋或篩選資產以快速定位。

**為何是此優先級**：提升導航效率，支援不同工作視角，直接影響可用性。

**獨立驗收**：建立多筆專案與提示詞後，切換視圖並執行搜尋/篩選，驗證結果集與顯示狀態正確且切換狀態持續記憶。

**驗收情境**：

1. **前提** 列表已載入多筆提示詞，**當** 搜尋關鍵字或標籤，**則** 結果只包含符合標題/標籤/正文的項目並高亮匹配片段。
2. **前提** 使用者位於列表視圖，**當** 切換至看板，**則** 資產依狀態/優先級泳道呈現，並保留已套用的篩選條件；返回列表後條件仍生效。

> 註：UI-002 為 FR-002 的「可驗收化」描述（同一需求，不是額外功能）。

---

### 使用者故事 3 - 版本備份與歷史檢視（優先級：P3）

使用者可在重要事件後建立版本節點，每日自動快照，並一鍵觸發立即備份；可查看歷史列表並開啟舊版內容。

**為何是此優先級**：確保內容安全與可回溯，降低誤刪或誤編輯的風險。

**獨立驗收**：在單一提示詞上建立多次編輯與手動備份，驗證每日快照任務與歷史列表可顯示並開啟指定版本。

**驗收情境**：

1. **前提** 系統已設定備份目錄，**當** 使用者點擊「建立版本節點」，**則** 新節點記錄標題/時間/摘要並出現在歷史列表，可開啟檢視。
2. **前提** 每日排程啟用，**當** 到達排程時間，**則** 產生當日快照並顯示於歷史列表；若失敗，顯示錯誤並可重試。
3. **前提** 使用者進行大量編輯後，**當** 觸發立即備份，**則** 建立最新快照且不阻塞編輯流程。

---

### 使用者故事 4 - 暫存區檢視與簡修（優先級：P3）

使用者可檢視匯入的暫存項目，對標題/刪減/註記進行最小幅度編修，並看到明確提示：歸檔由外部工具處理。

**為何是此優先級**：讓外部匯入流程有落地入口，同時避免混淆歸檔責任。

**獨立驗收**：建立多筆暫存項並開啟暫存區，編輯標題與註記，確認提示文案與資料保存正確。

**驗收情境**：

1. **前提** 暫存區有新匯入項目，**當** 使用者開啟暫存區，**則** 項目依時間排序並顯示來源與建議標籤。
2. **前提** 使用者對暫存項目修改標題或備註，**當** 保存後，**則** 變更立即反映且顯示提醒「歸檔由外部工具處理」。

### 邊界情境（Edge Cases）

- 外部檔案異動（新增/移動/刪除）與本地編輯衝突時，需提示衝突並允許重新整理或覆寫。
- 附件同名或缺少附件目錄時，需自動改名或提示設定錯誤，避免覆蓋。
- 搜尋/篩選無結果時，顯示「無結果」並允許清除條件。
- 自動保存/備份失敗時，提供重試與錯誤訊息，不阻塞編輯。
- 快照配額不足或儲存空間不足時，提示並導引清理或更換目錄。
- 刪除/復原後需立即更新索引與 UI（側邊欄、列表/看板、Detail Panel），並透過同步機制通知。
- 刪除/復原時附件一併處理：若回收站中的附件資料夾缺失或無法搬移，需顯示可理解錯誤並允許重試（不得靜默遺失附件）。
- 回收站自動清理：到期清理失敗時需顯示錯誤並允許重試；不得在無提示下「部分刪除」造成狀態不一致。
- 復原衝突：復原時若目標路徑已存在同名檔案/資料夾（含附件資料夾），必須阻擋並提供使用者明確選擇（覆蓋/改名/取消）；不得靜默覆蓋。
- 回收站視圖：回收站為空時需顯示 empty state；可一鍵清除篩選條件。

#### Edge Case Acceptance Scenarios（具體可驗收）

1. **外部檔案異動衝突：同檔被外部修改**

	**Given** 使用者已在提示詞 Detail Panel 開啟某提示詞並開始編輯（本地存在未保存變更），且檔案監控偵測到同一檔案被外部工具修改，
	**When** 系統偵測到衝突並準備 autosave 或重新載入該檔案內容，
	**Then** UI 必須顯示「衝突」狀態並提供至少兩個明確動作：
	- 重新整理（丟棄本地未保存變更，載入磁碟最新）
	- 覆寫保存（以本地內容寫回磁碟；若覆寫失敗需顯示原因並可重試）
	且 Detail Panel 不可靜默改寫使用者正在編輯的內容。

2. **Autosave 失敗：寫檔權限/IO 失敗**

	**Given** 使用者在提示詞 Detail Panel 編輯內容，且資料根目錄暫時不可寫（例如權限被撤銷、磁碟滿、檔案被鎖定），
	**When** 停筆觸發 autosave，
	**Then** UI 必須顯示「保存失敗」狀態與可理解原因，並提供「重試」與「複製未保存內容」等保護性動作；
	同時不得阻塞繼續編輯（仍可在 UI 暫存未保存內容），但必須持續顯示未保存警示直到成功寫入。

## 需求（必填）

### 功能需求

- **FR-001**: 系統必須允許建立、編輯、封存、刪除專案與提示詞，並保存標題、摘要/正文、狀態、優先級、標籤、備註、來源連結、更新時間。
	- Project.status 枚舉：`planned | in_progress | paused | done`。
	- Prompt.status 枚舉：`draft | needs_review | ready | deprecated`。
	- Prompt.priority 枚舉：`high | medium | low`。
	- 刪除語意：刪除必須移到回收站（`<rootPath>/.pah/trash/`）且可復原；封存僅為 `archived=true`（不移動檔案）。
	- 附件處理：刪除/復原必須一併移動該實體的附件資料夾（`<attachmentPath>/<entityType>/<entityId>/`）。
	- 復原衝突：若復原目的地已存在同名/同路徑檔案或附件資料夾，必須要求使用者選擇（覆蓋/改名/取消）。
		- `rename` 語意：`newSlug` 僅替換原本的 slug（同一路徑位置復原）；例如 prompt 僅改檔名、project 僅改資料夾名；不支援跨專案搬移復原。
	- 回收站自動清理（retention）：server 啟動時先執行一次清理；之後每日固定時間執行（例如 03:00，本機時區）；清理失敗需可觀測並允許重試。
	- 回收站操作：提供回收站列表與永久刪除（不可復原）能力；永久刪除需明確確認，並提供可理解的回饋。
- **FR-002**: 專案與提示詞列表須支援列表/看板視圖切換，並記住上次視圖狀態與套用的篩選條件。
	- 持久化：視圖/篩選屬於 UI 偏好，需透過 WorkspaceSettings API 落盤保存並可於重啟後重建；不得以 localStorage 作為權威來源。
	- 已封存視圖（Archive）：作為 Tools 的獨立入口（非 Projects/Prompts 子視圖），以單一視圖呈現已封存專案與已封存提示詞，並提供類型篩選切換。
- **FR-003**: 提示詞詳情頁必須支援正文與中繼資料同頁編輯，並在停止輸入 ≤ 2 秒內自動保存，顯示成功時間/失敗訊息。
- **FR-004**: 支援拖曳圖片/附件到編輯區，系統需移動至附件目錄、產生檔名並插入引用連結。
- **FR-005**: 提供搜尋與篩選：可依標題、標籤、正文全文檢索，並以狀態、優先級、標籤快速篩選；結果應可直接開啟詳情。
- **FR-006**: 暫存區必須顯示匯入項目並允許編輯標題/刪減/註記，清楚提示「歸檔由外部工具處理」，不提供歸檔操作。
- **FR-007**: 版本與備份：允許手動建立版本節點、每日自動快照、立即備份；歷史列表可按時間檢視並開啟指定版本內容。
- **FR-008**: 系統需偵測資料根目錄的新增/修改/搬移/刪除並即時更新側邊欄、列表/看板與詳情顯示。
- **FR-009**: 設定頁需允許設定資料根目錄、附件目錄、全域標籤（新增/改名/刪除/合併）、常用選項清單、備份設定；設定需驗證路徑與衝突。
	- 回收站保留天數（trash retention days）：預設 30 天，可於設定調整。
	- tagsDict 刪除語意：刪除 tag 不會批次改寫既有 Project/Prompt 檔案；僅影響 tagsDict（建議/選單），既有檔案中的 tags 保留。
	- backup.schedule 格式：採每日時間 `HH:mm`（24 小時制，本機時區）；格式不符時需顯示可理解錯誤並阻擋保存。
- **FR-010**: 所有操作需提供回饋：保存/備份/同步成功與錯誤訊息，錯誤不應阻塞其他可行操作。
- **FR-011**: 系統採單人本機模式，無登入/角色/權限管理；僅檢查資料根目錄與附件目錄存在且具讀寫權限，若無權限需提示並阻止寫入。
	- 路徑存在性：儲存設定時 `rootPath` 與 `attachmentPath` 必須已存在；若不存在需回 400 並提示先建立資料夾（server 不自動 mkdir）。
- **FR-012**: 版本節點與每日快照需保存正文、中繼資料與附件的完整複本；建立時若附件缺失或無法複製需提供錯誤與重試。

### UI／互動模式需求（可驗收）


- **UI-001（Sidebar）**：必須提供左側 Sidebar 作為主要導航，並採用「prototype + 規格入口」混合結構：
	- **Projects**：專案列表 / 專案看板
	- **Prompts**：提示詞列表 / 提示詞看板
	- **Tools**：暫存區（Inbox）/ 已封存（Archive）/ 回收站（Trash）/ 剪貼簿（Clipboard）/ 設定（Settings）
		- Archive：Tools 的獨立入口（非 Projects/Prompts 子視圖）；同一頁顯示已封存專案 + 已封存提示詞，並可用篩選切換類型。
	- 需包含「回收站」入口，提供回收站視圖（搜尋/篩選、復原、永久刪除）。
	- Sidebar 必須顯示目前選取的節點並維持單一選取狀態。
	- **驗收**：在 Sidebar 切換「提示詞」與「暫存區」，主內容區立即切換且不遺失目前篩選條件（除非使用者明確重設）。

- **UI-002（列表/看板切換）**：資產集合視圖必須支援「列表」與「看板」切換；切換不改變資料集合，只改變呈現方式。
	- **驗收**：在列表套用搜尋/篩選後切到看板，再切回列表，結果集保持一致。
	- **驗收補充**：重啟服務/重新載入頁面後，系統可從 WorkspaceSettings 還原上次的視圖模式與篩選條件；不得依賴 localStorage 才能恢復。


- **UI-003（右側 Detail Panel）**：選取列表/看板中的項目時，必須以「右側 overlay 滑入面板」顯示詳情並支援同頁編輯（正文 + 中繼資料）。
	- 需有 backdrop，並支援點擊 backdrop 關閉面板。
	- Detail Panel 需顯示保存狀態（Saving/Saved/Failed + 時間戳），並在失敗時提供可重試入口。
	- **驗收**：停筆 ≤ 2 秒觸發 autosave，狀態正確更新；重新載入後內容一致。

- **UI-004（回饋一致性）**：任何會改變資料的操作（新增/刪除/封存/還原/保存/備份/快照）必須提供一致的可見回饋：
	- 成功：顯示成功時間或狀態
	- 失敗：顯示可理解錯誤訊息 + 可重試入口
	- **驗收**：任一保存/備份失敗都不會靜默；使用者能在 1 步內重試。

> 註：UI-004 為 FR-010 的 UI 層可驗收化條款（同一需求，不是額外功能）。

### 主要實體（Key Entities）

- **Workspace**: 根目錄、附件目錄、全域標籤字典、常用選項、備份設定、外部整合授權資訊。
- **Project**: 識別碼、標題、摘要、狀態、專案類型、標籤、關聯檔案、更新時間、封存狀態。
	- status: `planned | in_progress | paused | done`
- **Prompt**: 識別碼、所屬專案、標題、狀態（草稿/待優化/可用/停用）、優先級、標籤、來源連結、備註、正文、更新時間、封存狀態。
	- status: `draft | needs_review | ready | deprecated`
	- priority: `high | medium | low`
- **Snippet**: 識別碼、標題、分類、內容、最近使用時間（供片語快速插入）。
	- 落盤：每個 Snippet 為單一檔案，集中於 `<rootPath>/.pah/snippets/`；可掃描重建。
- **InboxItem**: 識別碼、標題、來源平台/連結、匯入時間、原始內容、清理狀態、建議歸檔目的地與標籤。
- **Attachment**: 檔名、類型、來源、儲存位置、關聯對象（Project/Prompt/InboxItem）。
- **VersionEvent**: 事件類型（匯入成功/歸檔/刪除/每日快照/手動備份）、事件時間、訊息、受影響範圍。

## Invariants（不可違反）

- **INV-001（檔案為唯一權威）**：磁碟上的檔案內容（frontmatter + markdown body + 附件檔案）是唯一真實來源；任何 UI 顯示狀態都必須可由檔案推導。
- **INV-002（掃描可重建）**：在清空記憶體索引/重啟服務後，只要掃描資料根目錄即可完整重建 Sidebar、列表/看板、Detail Panel 所需的所有顯示資料。
	- Snippet 也必須可由掃描 `<rootPath>/.pah/snippets/` 重建（不得只存在於前端 store 或 localStorage）。
- **INV-003（不允許 UI 私有真實狀態）**：UI 不得持有無法落盤/無法重建的「私有真實狀態」（例如只存在於 localStorage 的權威欄位值、只存在於前端 store 的最終狀態）。
	- 允許：純展示偏好（例如視圖模式、欄位寬度）作為非權威狀態。
